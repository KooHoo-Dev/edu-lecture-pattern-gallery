## 2. 패턴별 표

'게임?' 은 교안 예제가 게임 상황인지다 (md 의 상황 / `.cs` 예제를 따로 적는다).

### 2-1. 생성

| 패턴 | 강조점 | 예제 상황 | 게임? | 다루는 함정 |
|---|---|---|---|---|
| Singleton | 하나만 있음 + 전역 통로. **씬 유지와 씬 종속을 구분하는 것이 핵심**. 형태 다섯: 순수 C# (`??=`), Mono + `DontDestroyOnLoad` + 중복 파괴, 씬 종속 + `OnDestroy` 에서 비우기, `ScriptableObject` 설정 (`Resources.Load`), 제네릭 베이스 | GameManager 점수, SoundManager, Normal/Boss StageManager, GameSettings, Config/SaveManager | 게임 / 게임 | 중복 생성(뒤에 온 것을 파괴, 앞의 것을 밀어내기), 씬이 바뀐 뒤의 Instance. "남용은 독" 절은 제목만 있고 비어 있다 |
| Factory Method | 무엇을 만들지는 자식이, 만드는 절차(`Spawn`: 생성 → 위치)는 부모가. 사용부는 추상 타입으로 받는다 | 디펜스 웨이브 스포너 (if 문자열 분기) / 몬스터 스포너(속도·크기·장비 굴림), 드롭 테이블 | 게임 / 게임 | 생성부가 모든 구체 타입을 알고 종류마다 분기를 고친다. Troll, DungeonLoot '추가 시' 코드로 확장을 보인다 |
| Abstract Factory | 서로 어울리는 **세트**를 일관되게 만든다 | 웨이브 테마(숲/용암: 적·투사체·배경) / 던전 테마 + 보상, UI 다크/라이트 스킨 | 게임 / 게임, UI | 하드 코딩으로 짝을 맞추다 실수(세트가 어긋남), 사용부 의존성 |
| Builder | 단계별 조립, `this` 를 돌려주는 체인, Director(대장장이)가 등급 레시피로 조립 | 매개변수 10개짜리 검 생성자 / 캐릭터 빌더, 대장장이 검 (등급 굴림, 옵션) | 게임 / 게임 | 생성자 매개변수 폭발, 생성자 여러 개 폭발. 불변 필드는 생성자로 (주석) |
| Prototype | 완성된 견본을 복제. **얕은 복사와 깊은 복사** (`MemberwiseClone` + 목록 새로 만들기). 프리팹과 `Instantiate` 가 곧 프로토타입 | 정예 고블린 설정 반복 / 견본 적 복제 후 복제본 하나만 버프 | 게임 / 게임 | 참조 필드를 그대로 두면 복제본끼리 공유. 00 의 값/참조 내용과 바로 이어진다 |

### 2-2. 구조

| 패턴 | 강조점 | 예제 상황 | 게임? | 다루는 함정 |
|---|---|---|---|---|
| Adapter | 맞지 않는 인터페이스를 우리가 원하는 모양으로 감싼다. 핵심 코드를 외부 API 변화에서 보호. 래퍼와 거의 같은 말 | 상점 결제(카카오/라인 절차 차이) / 결제 어댑터, 로그 어댑터(유니티·파일·웹, 매개변수 많은 쪽에 맞춤) | 비게임 (게임 서비스 인프라) | 상점 코드가 API 마다 다른 절차를 전부 앎. `SimpleInput` 을 예로 듦 |
| Bridge | 기능 축과 구현 축을 합성(필드 참조)으로 잇는다. 상속의 곱셈을 합성의 덧셈으로 | 무기 × 속성 (FireSword, IceBow … 12개 클래스) / 무기 × 인챈트(런타임 교체), 알림 × 채널 | 게임 / 게임, 비게임 | 조합 폭발. 구조가 Strategy 와 거의 같다 (교안도 "같은 구조, 다른 활용") |
| Composite | 잎과 가지를 같은 인터페이스로, 가지는 자식에게 재귀 위임 | 농장 밭 칸과 구역 물 주기 / 파일·폴더 크기, 제네릭 `TreeNode<T>` 조직도 | 게임 / 비게임 | 개별과 묶음을 다르게 처리하면 중첩될수록 분기가 감당 안 된다 |
| Decorator | 같은 인터페이스로 감싸 런타임에 기능을 겹친다. 원본 불변, 붙이고 뗄 수 있다 | 작물 점수 보너스(상속 조합, bool 플래그) / **스탯 버프 중첩**(목록 핸들러), 커피 토핑(정석 감싸기) | 게임 / 게임, 비게임 | 상속 조합 폭발과 플래그 덩어리. 스탯 예제는 감싸기가 아니라 **수정자 목록** 구조라 커피 예제와 모양이 다르다 |
| Facade | 복잡한 하위 시스템을 창구 하나로 감춘다 | 명중 처리 5단계(데미지 계산, 팝업, 적용, 통지, 사망)를 공격이 일어나는 모든 곳이 반복 → `CombatSystem.Send` | 게임 (`.cs` 없음) | 규칙이 바뀌면 호출부 여러 곳을 고친다. 수업 프로젝트의 `CombatSystem` 과 이어짐 |

### 2-3. 행동

| 패턴 | 강조점 | 예제 상황 | 게임? | 다루는 함정 |
|---|---|---|---|---|
| State | 상태별 클래스, `Enter`/`Tick`/`Exit` 3박자, **전이는 `ChangeState` 한 곳**에서 (Exit/Enter 짝), 상태 재사용, 상태 상속으로 확장(`GreenWithLeftState`) | 슬라임 AI 대기→추격→공격→사망을 **enum + 거대 switch** 로 / 신호등 순환 | 게임 / 비게임 | switch 비대, 진입·이탈 1회 처리가 어려움(공격 진입 때 이동 멈춤, 이탈 때 복구), 상태 로직이 몬스터 안에 갇힘 |
| Strategy | 알고리즘을 객체로, 런타임 교체. **State 와 헷갈리지 않기**(전이가 있으면 State) | 디펜스 타워 조준(가까운/강한/선두)을 if 로 / 쿠폰 할인 | 게임 / 비게임 | 흔한 실수 절: State 와 혼동, 전략에 상태를 잔뜩 넣기, 전략이 하나뿐 |
| Observer | 1:N 통지, 주체는 구독자를 모른다. **인터페이스 + 목록** 방식(`IHpObserver`, `Subscribe` 에서 `Contains` 로 중복 방지)과 **제네릭 + event** 방식(`Observable<T>`, 같은 값이면 알리지 않음) | 플레이어가 HP 바·사운드·업적을 직접 부름 / HP `Observable<int>` 에 람다 구독 | 게임 / 게임 | 강한 결합. **구독 해제(`OnDisable`)와 람다 해제 불가는 다루지 않는다** |
| Template Method | 뼈대(순서)는 부모가 고정, 달라지는 단계만 자식이 | 적과 보스의 `Setup` 복붙(컴포넌트 → 스탯 → 체력 채움 → 등록) | 게임 (`.cs` 없음) | 절차 변경이 복붙한 여러 곳에 번진다 |
| Command | 요청을 객체로: 실행, 취소, 큐잉, 기록. 입력과 동작 분리 | 농사 경작·심기·철거를 즉시 실행해 되돌리기 불가 | 게임 (`.cs` 없음) | 기록이 없으면 취소·재실행·예약 불가. **Undo 를 '실행의 반대'(`tile.Remove()`)로 가르친다** (3절) |

## 3. 이미 만든 표본과 교안 비교

표본은 고치지 않는다. 빠진 강조점은 다음 표본이나 교안 쪽 보강 후보로 적는다.

### 상태 (`state-player-actions`)

- 교안은 **적 AI(슬라임) + enum/switch** 를 나쁜 예로 쓰고, 표본은 **플레이어 + bool 플래그** 를 쓴다. 수강생이 둘 다 짜므로 어긋남은 아니지만, 교안 수업 바로 뒤에 보여 주면 상황이 다르다.
- 빠진 강조점: (1) 같은 상태 클래스를 **다른 몬스터가 재사용**, (2) **상태 상속으로 확장**(`GreenWithLeftState`), (3) 진입 때 이동 멈춤 → 이탈 때 복구처럼 **Enter 에서 바꾼 값을 Exit 에서 되돌리기** (표본은 공격 판정 `HitboxOn` 으로 같은 것을 보이므로 원리는 있다).
- 다음 후보: `state-drone-ai` (enum/switch 나쁜 예, 잔해 드론 AI). 선정 문서 3절.

### 관찰자 (`observer-health-events`)

- 교안의 주 구현은 **`IHpObserver` 인터페이스 + `List` 구독 목록**이고, 표본은 **C# `event`** 다. 교안을 들은 수강생은 "왜 인터페이스가 아니냐" 고 물을 수 있다. 표본 글(`body` 나 `mistakes`)에 두 방식의 대응(인터페이스 목록 = event 의 손 구현)을 한 줄 넣는 보강을 권한다 (표본 수정은 별도 결정).
- 빠진 강조점: (1) **중복 구독 방지** (`Contains`. C# `event` 는 같은 메서드를 두 번 `+=` 하면 두 번 부른다), (2) **같은 값이면 알리지 않기** (`Observable<T>` 의 `EqualityComparer`), (3) 목록 방식에서 알림 도중 구독 해제하면 `InvalidOperationException` (event 방식은 안전).
- 반대로 표본이 교안보다 앞선 것: `OnEnable`/`OnDisable` 짝, 람다 해제 불가, 붙을 때 지금 값 맞추기. 교안의 `Observable<T>` 데모가 바로 람다 구독이라, 교안 쪽에 해제 이야기를 더할 만하다.

### 명령 (`command-undo-replay`)

- **교안과 표본이 반대로 가르치는 지점이 있다.** 교안 `PlantCommand.Undo() => tile.Remove()` 는 '실행의 반대' 방식이다. 이미 심어진 칸에 심기를 실행하면(아무 일도 안 일어남) 되돌리기가 원래 있던 작물을 지운다. 표본은 바로 이 방식('반대 방향으로 한 칸')을 나쁜 예로 보이고 '이전 상태 저장' 을 정답으로 둔다. 수업에서 같은 날 둘을 보면 혼란이 생기므로 **교안 쪽 보강**(Execute 때 칸의 이전 상태를 저장)을 권한다. Jay 에게 묻는다 (선정 문서 7절).
- 빠진 강조점: **큐잉/예약**(명령을 줄 세워 나중에 실행). 표본은 리플레이로 '다시 실행' 만 보인다. 뒤 표본(예: 드론 이동 예약)으로 미룬다.

## 4. 갤러리 표본 적합도

기준 세 가지: (가) 같은 입력에서 나쁜 예의 버그가 미니 월드와 사건 기록에 보이는가, (나) 규칙을 순수 C# 코어에 두고 dotnet 으로 대조할 수 있는가, (다) 수강생이 실제로 겪는 증상인가.

| 패턴 | (가) 무대 | (나) 코어·대조 | (다) 증상 | 판정 | 갤러리 상황 (외곽 탐사대) |
|---|---|---|---|---|---|
| Prototype | ◎ 한 대에 단 모듈이 모든 복제본과 견본에 생긴다 | ◎ `Clone()` 순수 C# | ◎ 얕은 복사, `ScriptableObject` 견본을 런타임에 고쳐 에셋이 바뀜 | **묶음 2** | 격납고에서 견본 정찰 드론 복제 |
| Decorator | ◎ 버프가 모두 끝났는데 출력 막대가 기본값으로 안 돌아온다 | ◎ 시간 흐름(`Tick`) + 감싸기 사슬 | ◎ "버프 끝났는데 공격력이 그대로", 코루틴 중단으로 빼기를 건너뜀 | **묶음 2** | 하린의 출력 버프 (냉각 셀, 과부하) |
| Strategy | ○ 조준 표시와 실제 발사 대상이 엇갈린다 | ◎ 결정적인 드론 이동 + 고르기 | ○ if 사슬을 여러 곳에 복사하다 한 곳만 고침 | **묶음 2** | 정비 기지 포탑의 조준 방식 |
| Singleton | ○ 기지로 돌아오면 BGM 두 겹, 크레딧 0, 파괴된 매니저 호출 | △ 규칙(`SingleSlot`)은 순수 C# 이지만 씬 수명은 Target/sim 이 흉내 | ◎ 수업 프로젝트에서 가장 흔한 싱글턴 사고 | **묶음 2** (위험 표시) | 기지 ↔ 탐사 구역 씬 전환 |
| Factory Method (+ Template Method) | ○ 새 드론 종류가 기본 드론으로 나오거나, 레이더에 안 잡혀 웨이브가 끝나지 않는다 | ◎ | ○ 교안 데모의 `Random.Range(0, 2)` 가 바로 '추가한 종류가 안 나옴' | 묶음 3 | 잔해 드론 스포너 |
| Facade | ○ 함정으로 쓰러뜨린 드론이 HP 0 인데 남는다 | ◎ | ○ 호출부마다 절차를 복사하다 한 곳에서 단계를 빠뜨림 | 묶음 3 | 명중 처리 창구 |
| State (적 AI) | ◎ 추격으로 돌아가도 이동이 멈춘 채 | ◎ | ◎ 교안의 주 예제 | 묶음 3 | 잔해 드론 AI |
| Composite | ○ 편대 안 편대가 귀환 명령을 못 받는다 | ◎ | △ 한 단계만 도는 `foreach` | 묶음 3 뒤 | 드론 편대 |
| Abstract Factory | ○ 숲 구역에 용암 투사체 (세트 어긋남) | ◎ | △ 교안 코드 자체가 그 실수를 한다 (5절) | 묶음 3 뒤 | 구역 테마 세트 |
| Adapter | △ 두 센서 API 의 단위가 달라 막대가 넘친다 | ◎ | △ SDK 직접 호출이 흩어짐 | 보류 | 통신 장비 두 종류 |
| Bridge | ✕ 조합 폭발은 클래스 수 문제라 실행 중 버그가 없다 | ◎ | △ | **전략 표본에 녹인다** ("포탑 종류 × 조준 방식을 상속으로 곱하지 않는다") | — |
| Template Method | ✕ 단독으로는 절차 복붙의 유지보수 문제 | ◎ | △ | **팩토리 표본에 녹인다** (`Spawn` 이 템플릿, `CreateDrone` 이 훅. 교안의 Factory Method 가 이미 그 모양) | — |
| Builder | ✕ 무대에서 보일 실행 중 버그가 약하다 (생성자 인자 순서가 바뀌는 정도) | ◎ | △ Unity 에서는 Inspector·SO 로 대신하는 일이 많다 | **뺀다** (프로토타입·팩토리 `mistakes` 에 '같은 형식 인자 순서 바뀜' 한 줄) | — |

무대에서 단독으로 보이기 어려운 것은 Bridge, Template Method, Builder 셋이다. 셋 다 교안의 '상황' 이 클래스 수나 복붙 같은 유지보수 문제라서다. Facade 도 같은 부류로 보였지만 '호출부 한 곳이 단계를 빠뜨림' 으로 실행 중 버그를 만들 수 있어 묶음 3 에 둔다.

## 5. 교안 쪽 메모 (갤러리 작업 밖, 참고)

읽다가 본 것이다. 갤러리 표본에는 영향이 없고, 교안을 손볼 때 참고하라고 적는다. 고치지 않았다.

| 파일 | 내용 |
|---|---|
| `1. Creational/01. Singleton/C_StageManager.cs` | `public StageManager Instance` 가 `static` 이 아니다. 객체마다 자기 Instance 를 가져 중복 검사가 동작하지 않는다. 보스 코루틴이 `MinionPrefab` 대신 `BossPrefab` 을 만든다 |
| `Singleton.md` | '남용은 독' 절이 비어 있다 |
| `02. Factory Method/A_MonsterSpawner.cs` | `Random.Range(0, 2)` (int 판은 끝을 포함하지 않음)라 `case 2` 의 Troll 이 나오지 않는다. 교안이 보이려는 '추가' 가 실행되지 않는다 |
| `Factory Method.md` | `MonoBehaviour` 파생 `Enemy` 를 `new Goblin()` 으로 만든다 (Unity 에서 경고, 컴포넌트로 동작하지 않음). `CreateEnemy` 에 `()` 가 빠졌다 |
| `03. Abstract Factory/A_DungeonTheme.cs` | `ForestDungeon.CreateProjectile` 이 `LeafArrow` 대신 `FireBall` 을 만든다. 교안이 경고하는 '세트 어긋남' 그 자체다 (표본 소재로도 쓸 만함) |
| `04. Builder/A_CharacterBuilder.cs` | 데모 문구에 실존 인물 이름이 있다. 갤러리에는 옮기지 않는다 (kit 콘텐츠 정책) |
| `05. Prototype/Prototype.md` | 예제 `Clone()` 에 `return copy;` 가 없다 |
| `02 인터페이스 & 추상클래스.md` | `public virtual void TakeHeal(int heal);` 는 몸체가 없어 컴파일되지 않는다 (`virtual` 은 몸체가 필요) |
| `04. Decorator/A_StatBuff.cs` | `Remove` 가 앞에서부터 돌며 `RemoveAt` 하고 멈추지 않는다. 주석은 "먼저 들어온 것 하나" 인데, 떨어진 같은 종류는 모두 지우고 바로 붙은 같은 종류는 건너뛴다 (데모에서는 우연히 하나만 지워진다) |
| `Decorator.md` | `Fertilizer` 에 생성자가 없고 `ICrop` 과 `IScorableCrop` 이 섞였다 |
| `3. Behavioral/01. State/A_TrafficLight.cs` | `Awake` 에서 첫 상태로 `ChangeState` 하지 않아 `CurrentState` 가 null 인 채 아무것도 하지 않는다 |
| `02. Strategy/A_Coupon.cs` | 전략(쿠폰)이 `IsUsed` 상태를 들고 받은 `Item` 을 직접 고친다. md 의 '전략에 상태를 잔뜩 넣기' 주의와 어긋난다. `OnePlusOneCoffee` 는 식품에도 적용된다 |
| `Command.md` | `Undo => tile.Remove()` ('실행의 반대'). 3절 참고 |
| `03. Observer/A_GenericObservable.cs` | 람다로 구독해 해제할 수 없다. 해제 이야기가 없다 |
