## 1. 공통 요구 사항

- Unity 6.3 LTS, C# 9, 새 Input System. 수업 프로젝트에 넣어 바로 돌릴 수 있어야 한다.
- 패턴 이름보다 **수강생이 실제로 겪는 증상**에서 시작한다. 효과 끄기(나쁜 예)가 그 증상을 재현한다.
- 게임 규칙은 순수 C# 코어에 둔다 (dotnet 대조와 '테스트하기 쉬운 구조' 수업을 함께).
- 원리의 출처는 Robert Nystrom 의 *Game Programming Patterns* (웹판 공개)와 Unity 전자책 *Level up your code with design patterns and SOLID* 를 우선 링크한다. 글과 코드는 새로 쓴다.

## 2. 그룹별 카드

### A 행동

**`state-player-actions` 상태 패턴: 플레이어 행동** ★

- 수업에서 왜 필요한가: 수강생 플레이어 코드의 가장 흔한 형태가 `isJumping`, `isAttacking` bool 덩어리다. 조작을 하나 더할 때마다 버그가 곱으로 는다.
- 무대와 시나리오: 걷다가 공격 중 점프, 공중에서 공격, 걷는 중 피격 (자동 데모). 공격 중 피격, 공중 공격 허용.
- 효과 끄기: bool 플래그 넷과 if 문. 공격 자세로 점프, 맞아도 공격이 이어짐, 경직 중 걷기와 점프.
- 확인된 대표작: 없음 (범용 기법). 출처: Nystrom 'State', Unity 전자책.
- 겹치는 표본: 없음. 이후 계층 상태 기계, 적 AI 상태 기계 표본의 바탕.

### B 연결

**`observer-health-events` 관찰자 패턴: 체력 알림** ★

- 수업에서 왜 필요한가: 플레이어가 UI, 사운드, 업적을 직접 들고 부르는 코드가 흔하고, 구독 해제를 잊어 생기는 MissingReferenceException 이 Unity 수업에서 가장 자주 나오는 오류 중 하나다.
- 무대와 시나리오: 싸우는 중 HP 바를 껐다 켬 (자동 데모), 피격음을 끄고 회복, 경고 색 들고 나기.
- 효과 끄기: 플레이어가 넷을 직접 부름. 파괴된 바를 부르다 예외가 나 아래 줄(소리, 업적, 게임 오버)이 실행되지 않음.
- 확인된 대표작: 없음 (범용 기법). 출처: Nystrom 'Observer', Microsoft C# 이벤트 문서, Unity 전자책.
- 겹치는 표본: UI 갤러리 `health-bar-trail` (체력 바 연출).

### C 데이터

**`command-undo-replay` 명령 패턴: 되돌리기와 리플레이** ★★

- 수업에서 왜 필요한가: 퍼즐·전략·레벨 에디터에서 되돌리기를 '반대로 움직이기' 로 만들다가 어긋나는 일이 흔하다. 입력 기록·리플레이·입력 재설정으로 이어지는 기초다.
- 무대와 시나리오: 정비사 도윤의 정비 드론이 격자 위를 이동. 벽에 막힌 이동을 섞은 뒤 되돌리기 (자동 데모), 되돌리기 뒤 새 입력으로 다시 하기 기록이 지워짐, 리플레이.
- 효과 끄기: 되돌리기를 '반대 방향으로 한 칸' 으로 구현. 벽에 막혀 안 움직인 명령을 되돌리면 한 칸 어긋난다 (이전 위치를 저장하지 않은 흔한 실수).
- 확인된 대표작: 없음 (범용 기법). 출처: Nystrom 'Command', Unity 전자책.
- 겹치는 표본: UI 갤러리 `input-rebinding` (입력과 동작을 떼어 놓기).

## 4. 쟁점과 결정

| 쟁점 | 결정 |
|---|---|
| 웹 무대가 C# 를 직접 실행할 수 없다 | 코어를 TS 로 같은 이름으로 옮기고, 같은 시나리오를 dotnet 으로 돌린 기록과 줄마다 대조한다 (kit 설계 4-2절) |
| 나쁜 예를 C# 로도 둘지 | 둔다. 효과 끄기 화면의 버그가 C# 에서도 그대로 일어나는지 같은 방식으로 대조한다. 파일럿 비용을 보고 줄일 수 있다 |
| Unity 장면에서 실제로 돌려 볼지 | v1 은 컴파일과 dotnet 대조까지. 장면 연결은 `unity.setup` 글로 |
